所有請求直接由瀏覽器發出，回應顯示於各端點下方。

        POST
        /api/v1/source/ingest/{market}
        注入原始資料 (標準格式)
        ▼
      

      

        

          用於 Fetch Layer 將原始資料推送到 FinDB。需提供完整的 IngestRequest 結構，
          包含 idempotency_key 防止重複注入。


          可用 market：crypto · us · fx · macro · wtx · global · tw · hk · cn
        

        

          
Path Parameter

          

            
名稱類型必填說明

            
marketstring必填市場代碼 (crypto / us / fx / macro / ...)

          

        

        

          
Request Body (IngestRequest)

          

            
欄位類型必填說明

            
dataset_keystring必填資料集鍵值 (如 crypto_eod)

            
sourcestring必填資料來源名稱 (如 bloomberg)

            
request_keystring必填上游請求識別碼

            
idempotency_keystring必填冪等鍵，防止重複注入

            
payloadobject必填原始資料 payload

            
fetched_atdatetime必填資料抓取時間 (ISO 8601)

Admin API

      管理維運層 — /api/v1/admin
    


    

      所有 Admin API 端點均需要 X-API-Key Header，請在左側設定欄填入 Admin API Key。
      操作會建立不可修改的 audit correction 記錄。
    


    
    

      

        GET
        /api/v1/admin/dq-issues
        查詢資料品質問題清單 (取得 issue_id)
        ▼
      

      

        

          列出標準化過程中產生的 DQ Issue 記錄。Resolve DQ Issue 端點所需的 issue_id 從這裡取得。

          建議先用 resolved=false 篩選出未解決的問題。
        

        

          
Query Parameters

          

            
名稱類型必填說明

            
resolvedboolean選填false = 未解決，true = 已解決，不填 = 全部

            
instrument_idUUID選填篩選特定商品

            
severitystring選填嚴重程度：warning / error

            
page / page_sizeinteger選填分頁

          

        

        

          
請求

          

            

              
              
            

            

              
              
            

            

              
              
            

            

              
              
            

          

          

            
          

        

        

          

            Response
            
          

          

        

      

    


    
    

      

        PATCH
        /api/v1/admin/eod/{instrument_id}/{trade_date}
        手動修正 EOD 收盤資料
        ▼
      

      

        

          修正特定商品特定日期的 OHLCV 欄位。只需提供要修改的欄位，未填的欄位保持不變。
          每次修正都會建立一筆 correction audit 記錄，保存修前/修後快照。
        

        

          
Path Parameters

          

            
名稱類型必填說明

            
instrument_idUUID必填商品 UUID

            
trade_datedate必填交易日期 YYYY-MM-DD

          

        

        

          
Request Body (PatchEODRequest)

          

            
欄位類型必填說明

            
correction_reasonstring必填修正原因說明（最多 2000 字）

            
opendecimal選填開盤價

            
highdecimal選填最高價

            
lowdecimal選填最低價

            
closedecimal選填收盤價

            
volumeinteger選填成交量

            
turnoverdecimal選填成交金額

          

        

        

          
請求

          

            

              
              
            

            

              
              
            

          

          

            

              
              
            

          

          

            
          

        

        

          

            Response
