① Source API 入口

路由分派 backend/app/api/v1/source.py

統一入口、市場守門、Direct vs 通用 schema
  • 通用端點：/ingest/{crypto,us,fx,macro,wtx,global,tw,hk,cn}
  • Direct 端點：/ingest/{usstock,hkchina,macro}/direct — 帶 metadata + data 結構
  • 市場守門：以 expected_market 對照 dataset.market，防跨市場誤投
  • SHA256 idempotency：_build_direct_ingest_request 對 payload 算指紋

③ DB 邊界 — Raw + Run 同步落地

raw.market_payload JSONB

原始 payload 完整保存 14 天
  • idempotency_key (PK)
  • payload JSONB（完整 fetch 內容）
  • expire_at = fetched_at + RAW_RETENTION_DAYS
  • run_id 對應 ingestion_run
  • 競態以 IntegrityError 處理

ingestion_run tracking

每次 ingest 一列，貫穿整個生命週期
  • run_id (UUIDv7)
  • status="pending" → processing → completed / completed_with_errors / failed
  • raw_records = payload 中 data 筆數
  • metadata_ 帶 source / request_key / 重跑來源

HTTP 回應 201

同步只到此為止，正規化之後才跑
  • success: true
  • run_id + status="pending"
  • 注意：客戶端拿到 pending ≠ 已進 canonical

④ 進 DB 後 — 背景正規化

路由分派 NORMALIZER_MAP

services/ingestion.py · 18 種 dataset
  • us_stock_eod → USStockNormalizer
  • us_equity_eod → EquityNormalizer
  • crypto_eod → CryptoNormalizer
  • macro_observation → MacroNormalizer
  • … 其餘覆蓋 fx / futures / 各市場 equity

欄位映射 map_fields

services/normalize/base.py
  • 用 dataset_config.field_mapping 解 dot-path
  • 標準化 symbol、trade_date、source
  • 產出 MappedRecord list

DQ 檢查 validators.py

分阻擋與警告兩級
  • error OHLC high/low、volume 負值、batch 內重複 → 跳過該筆
  • warning 缺 OHLC、單日漲跌 > 30% → 仍寫入
  • 所有問題寫入 dq_issue 表

Instrument 解析 instruments

維度表自動補齊
  • 優先用 identifier_type + identifier_value 對 instrument_identifier
  • 找不到 → get_or_create_instrument
  • 下市則跳過 / 警告

標準寫入 UPSERT

market_data_eod
  • 衝突鍵：(instrument_id, trade_date)
  • ON CONFLICT 更新 OHLC / volume / turnover / asof_ts / run_id
  • 這也是 rerun 安全的基礎

Run 收尾 update_run_status

最終狀態決定觀測指標

  • completed_at
  • completed · completed_with_errors · failed
  • 單一 transaction 提交

關鍵邊界提醒

同步只到落 raw

Source API 同步部分結束於 raw + run 落地，正規化是 BackgroundTasks，客戶端拿到 pending 不代表已進 canonical。要做完成通知需另建機制。

Idempotency 在 raw 層

已存在的 idempotency_key 連 raw 都不會重寫，直接回原 run_id。要強制重跑必須用 POST /runs/:id/rerun。

DQ error 只擋單筆

單筆壞掉不影響整批，run 會標 completed_with_errors。下游不能假設 run 成功 = 全部資料都進來。

Upsert 衝突鍵

canonical 衝突鍵為 (instrument_id, trade_date)，同一天重送會覆蓋 — 所以 rerun 與人工修正都安全。

無下游事件

canonical 寫入後 沒有 cache invalidation / webhook / 事件總線，Serve 直接打 DB。要加快取或通知是後續可拆功能點。

Raw 14 天保存

Rerun 必須在 RAW_RETENTION_DAYS 內進行，過期就無法從 raw 取回原始 payload。
